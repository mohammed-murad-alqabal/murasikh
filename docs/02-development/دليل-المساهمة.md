نحن ملتزمون بتوفير بيئة ترحيبية وآمنة للجميع، بغض النظر عن:
- الخلفية أو الهوية

- الدين أو المعتقد

- استخدام لغة ترحيبية وشاملة

## 🔄 كيف تساهم

### أنواع المساهمات

1. **الإبلاغ عن أخطاء** - أنشئ Issue مع وصف واضح
2. **اقتراح ميزات** - أنشئ Issue مع علامة `enhancement`
3. **تحسين التوثيق** - Git clone → تعديل → Pull Request
4. **كتابة كود** - اتبع الخطوات أدناه

## 🔧 عملية المساهمة

### 1. Fork المستودع

```bash
# Fork عبر GitHub UI ثم:
git clone https://github.com/YOUR_USERNAME/murassikh.git
cd murassikh
```

### 2. إنشاء فرع جديد

```bash
# تحديث main
git checkout main
git pull upstream main

# إنشاء فرع جديد
git checkout -b feature/my-feature
# أو
git checkout -b fix/my-fix
# أو
git checkout -b docs/my-docs
```

**قواعد تسمية الفروع:**

| النوع | المثال |
|-------|--------|
| ميزة جديدة | `feature/add-notification-system` |
| إصلاح خطأ | `fix/resolve-database-connection` |
| توثيق | `docs/update-api-reference` |
| تحسين | `refactor/optimize-embeddings` |

### 3. إجراء التغييرات

```bash
# كتابة الكود
# ...

# تشغيل الاختبارات
pytest

# تشغيل Linter
flake8 app/
black --check app/
isort --check-only app/
```

### 4. Commit التغييرات

```bash
# إضافة الملفات
git add .

# Commit مع رسالة واضحة
git commit -m "feat: add emotion classification system"
```

**قواعد رسائل Commit:**

استخدم [Conventional Commits](https://www.conventionalcommits.org/):

| النوع | الاستخدام |
|-------|----------|
| `feat` | ميزة جديدة |
| `fix` | إصلاح خطأ |
| `docs` | توثيق |
| `style` | تنسيق (لا يؤثر على الكود) |
| `refactor` | إعادة هيكلة |
| `test` | اختبارات |
| `chore` | مهام صيانة |

**أمثلة:**

```
feat: add offline support for Flutter app
fix: resolve database connection timeout issue
docs: update API authentication guide
refactor: optimize embedding creation process
```

### 5. Push وإنشاء Pull Request

```bash
# Push للفرع
git push origin feature/my-feature

# إنشاء Pull Request عبر GitHub UI
```

## ✅ قائمة التحقق قبل Pull Request

- [ ] الكود يتبع [معايير الكود](./معايير-الكود.md)
- [ ] الاختبارات تمر بنجاح
- [ ] لا توجد أخطاء في Linter
- [ ] التوثيق محدث (إذا لزم الأمر)
- [ ] رسائل Commit واضحة
- [ ] الفرع محدث مع main

---

## 📝 قالب Pull Request

```markdown
## الوصف
وصف واضح ومختصر للتغييرات.

## نوع التغيير
- [ ] إصلاح خطأ (fix)
- [ ] ميزة جديدة (feat)
- [ ] تحسين (refactor)
- [ ] توثيق (docs)

## كيف تم اختباره؟
وصف الاختبارات التي تم إجراؤها.

## لقطات الشاشة (إذا لزم الأمر)
لقطات شاشة للتغييرات المرئية.

## قائمة التحقق
- [ ] الاختبارات تمر
- [ ] التوثيق محدث
- [ ] لا توجد تعارضات مع main
```

## 🔍 عملية المراجعة

### ما نتوقعه منك

- الرد على التعليقات في الوقت المناسب
- إجراء التعديلات المطلوبة
- الصبر أثناء عملية المراجعة

### ما يمكنك توقعه منا

- مراجعة Pull Request خلال 3-5 أيام عمل
- تقديم تعليقات بناءة وواضحة
- المساعدة في تحسين الكود

## 🐛 الإبلاغ عن الأخطاء

### قبل الإبلاغ

1. ابحث في [Issues](#) للتأكد من أن الخطأ لم يُبلغ عنه
2. تأكد من استخدام أحدث إصدار

### قالب الإبلاغ

```markdown
## وصف الخطأ
وصف واضح ومختصر للخطأ.

## خطوات إعادة الإنتاج
1. انتقل إلى '...'
2. انقر على '...'
3. حرك المؤشر إلى '...'
4. الخطأ يظهر

## السلوك المتوقع
وصف ما كنت تتوقعه أن يحدث.

## لقطات الشاشة
إذا لزم الأمر، أضف لقطات شاشة.

## معلومات البيئة
- OS: [مثل: Ubuntu 22.04]
- Browser: [مثل: Chrome 120]
- Version: [مثل: 0.1.0]

## سياق إضافي
أي معلومات أخرى مفيدة.
```

## 💡 اقتراح ميزات

### قالب الاقتراح

```markdown
## ملخص الميزة
وصف واضح ومختصر للميزة المقترحة.

## المشكلة الحل
ما المشكلة التي تحلها هذه الميزة؟

## الحل المقترح
كيف ترى أن الميزة يجب أن تعمل؟

## البدائل
هل هناك حلول بديلة فكرت فيها؟

## سياق إضافي
رسومات توضيحية، أمثلة، إلخ.
```
