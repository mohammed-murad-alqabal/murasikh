# عقد API المعتمد — الإصدار v1

**حالة الوثيقة:** العقد التشغيلي الحالي
**آخر تحديث:** 2026-09-23
**Base URL:** `https://api.murassikh.com/api/v1`

هذه الوثيقة هي المرجع الحالي للمسارات التي يستخدمها التطبيق. لا تستخدم المسارات القديمة الواردة في وثائق تاريخية.

## المسارات الرسمية

| الطريقة | المسار | المصادقة | الغرض |
|---|---|---|---|
| `POST` | `/analyze` | اختيارية | تحليل النص وتقديم التوصية |
| `POST` | `/audio/analyze-audio` | اختيارية | تحليل ملف صوتي وإرجاع توصية |
| `POST` | `/home/verse` | اختيارية | إرجاع آية بناءً على إشارات السياق |
| `POST` | `/auth/register` | لا | إنشاء حساب |
| `POST` | `/auth/login` | لا | تسجيل الدخول |
| `POST` | `/auth/refresh` | refresh token | تدوير رمز التحديث |
| `POST` | `/auth/logout` | نعم | إبطال رمز التحديث الحالي |
| `GET` | `/history` | نعم | قراءة سجل المستخدم |
| `DELETE` | `/history` | نعم | حذف سجل المستخدم |
| `POST` | `/history/feedback` | نعم | حفظ تقييم التفاعل |
| `GET` | `/history/delayed` | نعم | جلب الردود المؤجلة المستحقة |
| `GET` | `/health/live` | لا | فحص liveness خفيف |
| `GET` | `/health/ready` | لا | فحص PostgreSQL وRedis وChroma |
| `GET` | `/health` | لا | alias للتوافق؛ لا يثبت readiness |

## عقد التوصية النصية

### الطلب

```json
{
  "text": "أشعر بالقلق والتوتر من المستقبل",
  "user_context": {
    "age": 30,
    "gender": "ذكر"
  },
  "chat_history": [
    {"role": "user", "content": "أشعر بالتعب"},
    {"role": "assistant", "content": "هل تستطيع وصف سبب التعب؟"}
  }
}
```

`text` مطلوب وطوله بين حرفين و1000 حرف. `user_context` اختياري ويخضع لنموذج Pydantic المشترك. `chat_history` اختياري ويقبل حتى 10 رسائل؛ يجب أن يكون الدور `user` أو `assistant`، وأن يتراوح محتوى الرسالة بين حرف واحد و2000 حرف. يستخدم العميل هذا السياق للجلسات غير المصادق عليها، بينما يبني الخادم السياق الأساسي للمستخدم المصادق عليه من سجله المعزول حسب الحساب.

### الرد

```json
{
  "emotion": "قلق",
  "confidence": 0.85,
  "tier": "moderate",
  "message": "...",
  "delayed_message": null,
  "source": "سورة الرعد: ٢٨",
  "tafsir": "...",
  "interaction_id": 12345
}
```

لا تستخدم الحقول القديمة `arabic_text` أو `content_type` أو `translation` كعقد أساسي لهذا المسار. يمكن دعمها فقط عبر طبقة توافق موثقة ومؤقتة إذا احتاج عميل قديم إليها.

## عقد Home

يستخدم التطبيق `POST /home/verse` وليس `GET /home/daily-verse`.

```json
{
  "dominant_emotion": "قلق",
  "confidence": 0.8,
  "signal_source": "face",
  "time_of_day": "مساء"
}
```

ويرد الخادم بصيغة:

```json
{
  "verse": "...",
  "source": "سورة الرعد: ٢٨",
  "tafsir": "...",
  "emotion_context": "قلق",
  "signal_used": "face",
  "confidence": 0.8,
  "cached": false
}
```

القيم المعتمدة لـ`signal_source` هي `face` و`audio` و`history` و`time`. وقيمة `confidence` بين 0 و1.

## عقد التغذية الراجعة

يستخدم التطبيق `POST /history/feedback`:

```json
{
  "id": 12345,
  "feedback": 1
}
```

القيم المسموحة لـ`feedback` هي `-1` و`0` و`1`. لا تستخدم الصيغة القديمة `interaction_id` و`is_positive` في العملاء الجدد.

## سياسة أخطاء مختصرة

- `401`: الرمز غير صالح أو انتهت الجلسة.
- `404`: السجل أو التفاعل غير موجود.
- `413`: الملف الصوتي أكبر من الحد.
- `422`: جسم الطلب لا يطابق العقد.
- `429`: تجاوز rate limit.
- `503`: readiness غير متحققة أو dependency غير متاحة.

## قواعد التغيير

أي تغيير في المسار أو method أو اسم حقل أو رمز حالة يتطلب تحديث هذه الوثيقة، واختبار Backend، وخدمة Flutter، ثم تشغيل CI. لا تُستخدم كلمة «مكتمل» في وثائق API قبل نجاح الاختبار الآلي المقابل.
