# عقد المصادقة — API v1

**حالة الوثيقة:** Current / مشتقة من FastAPI OpenAPI
**آخر تحديث:** 2026-09-25
**Base URL:** `https://api.murassikh.com/api/v1`

> لا يوجد endpoint `/auth/me` في العقد الحالي. لا تستخدم أمثلة JSON القديمة أو غلاف `success/data` من الوثائق التاريخية.

## المسارات

| الطريقة | المسار | المصادقة | الوصف |
|---|---|---|---|
| `POST` | `/auth/register` | لا | إنشاء حساب وإصدار access/refresh tokens |
| `POST` | `/auth/login` | لا | تسجيل الدخول عبر OAuth2 form |
| `POST` | `/auth/refresh` | لا | تدوير refresh token مرة واحدة |
| `POST` | `/auth/logout` | Bearer access | إبطال access/refresh للجلسة الحالية |
| `DELETE` | `/auth/account` | Bearer access | حذف الحساب وبياناته الخادمية بشكل ذري |
| `GET` | `/auth/export` | Bearer access | تصدير الحساب والتفاعلات |

## التسجيل

```http
POST /api/v1/auth/register
Content-Type: application/json
```

```json
{
  "username": "ahmed_123",
  "email": "ahmed@example.com",
  "password": "SecurePass123"
}
```

القيود التنفيذية:

- `username`: بين 3 و50 حرفاً، ويسمح بـ`A-Z a-z 0-9 _ . -`.
- `password`: بين 8 و128 حرفاً. يستخدم الخادم Argon2id.
- `email`: اختياري، بحد أقصى 254 حرفاً. يجب أن يكون قرار إلزامه أو التحقق الصارم منه تغييراً موثقاً منفصلاً.

استجابة النجاح `200`:

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "refresh_token": "..."
}
```

## تسجيل الدخول

يستخدم `OAuth2PasswordRequestForm`، وليس JSON:

```http
POST /api/v1/auth/login
Content-Type: application/x-www-form-urlencoded
```

```text
username=ahmed_123&password=SecurePass123
```

استجابة النجاح `200` بنفس شكل التسجيل. الفشل في بيانات الاعتماد يعيد `401`.

## تدوير Refresh Token

```http
POST /api/v1/auth/refresh
Content-Type: application/json
```

```json
{"refresh_token": "..."}
```

كل refresh token يستخدم مرة واحدة. يعيد الخادم access token وrefresh token جديدين. يصبح refresh القديم غير صالح بعد التدوير أو logout أو حذف الحساب.

## تسجيل الخروج

```http
POST /api/v1/auth/logout
Authorization: Bearer <access_token>
```

يعيد `200`، ويرفع الخادم `session_version` ويبطل `refresh_jti`. لذلك تُرفض الطلبات اللاحقة باستخدام access token نفسه بـ`401` فوراً.

## حذف الحساب

```http
DELETE /api/v1/auth/account
Authorization: Bearer <access_token>
```

الحذف ذري في PostgreSQL ويشمل:

- سجل المستخدم.
- `interactions`.
- `delayed_responses`.
- `app_ratings` المرتبطة بالحساب.

استجابة النجاح `200`:

```json
{
  "message": "Account and account-owned data deleted",
  "deleted_user_id": 123
}
```

على العميل، بعد نجاح الطلب، حذف access/refresh tokens وصناديق Hive وsettings وnotifications وملفات export المحلية. لا يعني حذف PostgreSQL حذف سجلات مزود الذكاء الاصطناعي أو النسخ الاحتياطية الخارجية؛ ذلك يخضع لسياسة الاحتفاظ المعلنة.

## تصدير البيانات

```http
GET /api/v1/auth/export
Authorization: Bearer <access_token>
```

يعيد بيانات الحساب والتفاعلات فقط، ولا يعيد `password_hash` أو الرموز. يفضّل للعميل عدم كتابة نسخة التصدير إلى ملف دائم غير محمي.

## رموز الأخطاء

| الرمز | المعنى |
|---|---|
| `400` | اسم المستخدم أو البريد موجود مسبقاً |
| `401` | رمز غير صالح، جلسة مبطلة، refresh مستعمل، أو بيانات اعتماد خاطئة |
| `422` | جسم أو form لا يطابق القيود |
| `429` | تجاوز rate limit |
| `500` | خطأ داخلي بعد rollback |
