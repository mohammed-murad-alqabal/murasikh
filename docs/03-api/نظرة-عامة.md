# نظرة عامة على API v1

هذه الوثيقة تصف المسارات الفعلية الحالية في Backend. المرجع التفصيلي للعقود هو [العقد المعتمد](./العقد-المعتمد.md).

## المعلومات الأساسية

| البند | القيمة |
|---|---|
| Base URL | `https://api.murassikh.com/api/v1` |
| الإصدار | v1 |
| التنسيق | JSON، باستثناء رفع الصوت |
| المصادقة | JWT Bearer للمسارات التي تتطلب حساباً |
| الحالة | MVP تجريبي / staging candidate |

## المسارات

| الطريقة | Endpoint | المصادقة | الوصف |
|---|---|---|---|
| `POST` | `/analyze` | اختيارية | تحليل النص وتقديم التوصية |
| `POST` | `/audio/analyze-audio` | اختيارية | تحليل الصوت |
| `POST` | `/home/verse` | اختيارية | آية سياقية من إشارات الجهاز |
| `POST` | `/auth/register` | لا | التسجيل |
| `POST` | `/auth/login` | لا | تسجيل الدخول |
| `POST` | `/auth/refresh` | refresh token | تدوير رمز التحديث |
| `POST` | `/auth/logout` | نعم | تسجيل الخروج وإبطال access/refresh للجلسة |
| `DELETE` | `/auth/account` | نعم | حذف الحساب والبيانات الخادمية المملوكة |
| `GET` | `/auth/export` | نعم | تصدير بيانات الحساب والتفاعلات |
| `GET` | `/history` | نعم | قراءة السجل |
| `DELETE` | `/history` | نعم | حذف السجل |
| `POST` | `/history/feedback` | نعم | حفظ تقييم التفاعل |
| `GET` | `/history/delayed` | نعم | الردود المؤجلة المستحقة |
| `GET` | `/health/live` | لا | liveness |
| `GET` | `/health/ready` | لا | readiness للاعتماديات |
| `GET` | `/health` | لا | alias للتوافق، وليس readiness |

## المصادقة

```http
POST /api/v1/auth/login
Content-Type: application/x-www-form-urlencoded

username=user_123&password=secure_password
```

تستخدم الطلبات المحمية:

```http
Authorization: Bearer <access-token>
```

## تنسيق الأخطاء

تعتمد أخطاء FastAPI القياسية عند فشل التحقق، ومنها `422`. وتستخدم المسارات رموز `401` و`404` و`413` و`429` و`503` حسب الحالة. لا تفترض أن كل المسارات تعيد غلافاً موحداً من نوع `success/data`؛ يجب الرجوع إلى نموذج كل endpoint.

## أمثلة الصحة

```bash
curl https://api.murassikh.com/api/v1/health/live
curl https://api.murassikh.com/api/v1/health/ready
```

يرجع `/health/ready` حالة `503` إذا فشل PostgreSQL أو Redis أو Chroma.

## حدود الاستخدام

تحدد rate limits في الكود لكل مسار، ولا يجوز اعتبار أرقام الخطط القديمة مثل 50 طلباً في الساعة أو Premium غير المحدود عقداً عاماً ما لم تُنفذ وتُثبت في الإعدادات.

## قواعد التغيير

أي تغيير في path أو method أو request/response field أو status code يتطلب تحديث وثيقة العقد المعتمد، والعميل Flutter، واختبار Backend، ثم تشغيل CI.
