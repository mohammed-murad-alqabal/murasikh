# اختبار أداء Chroma والبحث الدلالي الحقيقي

## الغرض

تستخدم اختبارات CI بيانات وهمية لقياس كلفة الخوارزمية بشكل ثابت. أما هذا الاختبار الاختياري فيقيس المسار الحقيقي الذي يتضمن نموذج `SentenceTransformer` وChroma وقاعدة القرآن المحلية. لا يُشغّل تلقائيًا في CI لأنه قد ينزّل نموذجًا كبيرًا ويحتاج إلى قاعدة Chroma مهيأة.

## التهيئة

من مجلد `backend`، جهّز قاعدة القرآن أولًا:

```bash
cd backend
export CHROMA_PATH="$PWD/chroma_db"
python scripts/seed_quran.py --reset --batch-size 128
```

بعد نجاح التهيئة، شغّل Benchmark الحقيقي:

```bash
python scripts/benchmark_semantic_rag.py \
  --iterations 30 \
  --warmup 3 \
  --n-results 5 \
  --results perf-results/semantic-rag-real.json
```

ينتج الملف تقريرًا بصيغة JSON يتضمن حجم Collection، ومتوسط الزمن، و`p50` و`p95` و`p99` ومعدل العمليات في الثانية لمساري البحث واختيار الآية المحلي.

## تفسير النتائج

قارن النتائج مع خط أساس محفوظ لكل بيئة تشغيل، ولا تقارن جهازًا محليًا ضعيفًا مباشرة بمشغل CI. أي ارتفاع مستمر في `p95` بأكثر من 25% عن خط الأساس يستدعي فحص النموذج، حجم Collection، الذاكرة، ونوع التخزين. يجب تسجيل اسم النموذج، عدد الآيات، إصدار Python، ونوع CPU/GPU مع كل تقرير.

هذا Benchmark لا يقيس زمن Gemini ولا زمن الشبكة؛ قياس المزود الخارجي يجب أن يكون منفصلًا وبحدود تكلفة واضحة. كما أن `seed_quran.py --verify` هو فحص سلامة سريع ولا يعيد بناء النموذج.
