# اختبار الأجهزة والقفل الحيوي

## الهدف

تتحقق هذه الخطة من عمل القفل التلقائي والمصادقة الحيوية على جهاز فعلي. اختبارات `AutoLockPolicy` الموجودة في Flutter تتحقق من منطق المهلة ودورة الحياة، لكنها لا تستطيع محاكاة مستشعر البصمة أو Face ID أو حوار نظام التشغيل؛ لذلك يجب تنفيذ السيناريوهات التالية يدويًا أو عبر جهاز مختبر متصل.

## المتطلبات

يجب تثبيت Flutter، وتسجيل بصمة أو وجه واحد على الأقل في الجهاز، وتفعيل قفل الشاشة، ومنح التطبيق أذونات المصادقة التي يطلبها نظام التشغيل. شغّل التطبيق بعنوان Backend مناسب للبيئة:

```bash
cd frontend
flutter pub get
flutter devices
flutter run --dart-define=API_BASE_URL=https://backend.example.com -d <device-id>
```

لا تستخدم بيانات إنتاج حقيقية أثناء الاختبار؛ استخدم حسابًا تجريبيًا وبيانات لا تحتوي على معلومات شخصية.

## مصفوفة الاختبار

| المنصة | الجهاز المقترح | المصادقة | النتيجة المتوقعة |
|---|---|---|---|
| Android | جهاز فعلي API 29 أو أحدث | بصمة، ثم Face Unlock إن توفر | تظهر بوابة القفل، ينجح الفتح عند المصادقة الصحيحة |
| Android | محاكي مع بصمة مسجلة | محاكاة بصمة ناجحة وفاشلة | يتغير الحوار حسب نجاح المصادقة أو إلغائها |
| iOS | جهاز فعلي يدعم Face ID | Face ID ناجح وفاشل | تظهر رسالة الاستخدام وتُفتح البوابة بعد النجاح |
| iOS | جهاز فعلي يدعم Touch ID | Touch ID ناجح وفاشل | يعمل القفل دون الاعتماد على Face ID |
| iOS Simulator | محاكي مع Face ID enrolled | محاكاة النجاح والفشل | اختبار مساعد، وليس بديلًا عن الجهاز الفعلي |

## السيناريوهات

### التفعيل والفتح

1. افتح إعدادات الخصوصية داخل التطبيق.
2. فعّل المصادقة الحيوية.
3. أغلق التطبيق وافتحه مجددًا.
4. تحقق من ظهور عبارة **التطبيق مقفل** وعدم إمكانية استخدام الشاشة أسفلها.
5. نفّذ مصادقة ناجحة وتحقق من فتح التطبيق.
6. أعد تشغيل التطبيق وتأكد من استمرار الإعداد.

### العودة من الخلفية

1. فعّل المصادقة الحيوية.
2. افتح التطبيق ثم أرسله إلى الخلفية لمدة قصيرة.
3. أعده إلى الواجهة.
4. تحقق من إعادة القفل وظهور حوار المصادقة.
5. ألغِ الحوار وتأكد من بقاء التطبيق مقفلًا.
6. نفّذ مصادقة ناجحة وتأكد من استعادة الاستخدام.

### مهلة القفل

1. عطّل المصادقة الحيوية وفعّل القفل التلقائي.
2. اختر مهلة 30 ثانية.
3. اترك التطبيق دون لمس لمدة 30 ثانية على الأقل.
4. تحقق من ظهور بوابة القفل.
5. المس الشاشة قبل انتهاء المهلة وتأكد من إعادة ضبط المؤقت.
6. عطّل القفل التلقائي وتأكد من عدم القفل بعد مرور وقت طويل.

### حالات الفشل

اختبر بصمة أو وجهًا غير صحيح، ثم الإلغاء، ثم رفض الإذن من إعدادات النظام. يجب ألا يفتح التطبيق في هذه الحالات، ويجب أن تظهر رسالة قابلة للفهم مع زر **فتح التطبيق** لإعادة المحاولة. تحقق كذلك من أن التطبيق لا يعرض محتوى حساسًا فوق طبقة القفل.

## معايير القبول

يُقبل الإصدار عندما تنجح جميع الحالات التالية على جهاز Android فعلي وجهاز iOS فعلي: بدء القفل، المصادقة الناجحة، المصادقة الفاشلة، الإلغاء، العودة من الخلفية، مهلة 30 ثانية، تعطيل القفل، واستمرار الإعداد بعد إعادة التشغيل. سجّل إصدار النظام وإصدار التطبيق ونتيجة كل حالة في تقرير الإصدار.

## حدود CI

لا تُشغّل هذه الحالات داخل GitHub Actions الحالي؛ البيئة السحابية لا تحتوي على مستشعر بصمة أو Face ID ولا تملك جلسة نظام تشغيل جوال. يظل CI مسؤولًا عن التحليل الساكن واختبارات سياسة القفل، بينما يعتمد اختبار المصادقة الفعلية على جهاز مختبر أو خدمة أجهزة حقيقية.
