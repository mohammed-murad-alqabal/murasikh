# 🔄 استراتيجية التهجير (Data Migration Strategy)

استراتيجية تهجير البيانات وتحديث قاعدة البيانات لمشروع مُرَسِّخ.

---

## 📋 الهدف

ضمان تهجير آمن ومتسق للبيانات بين الإصدارات المختلفة من قاعدة البيانات، مع إمكانية التراجع واستمرارية الخدمة.

---

## 🎯 المبادئ الأساسية

1. **Zero Downtime** - عدم انقطاع الخدمة أثناء التهجير
2. **Reversibility** - إمكانية التراجع عن أي تغيير
3. **Testing First** - اختبار جميع التهجيرات في بيئة الاختبار
4. **Backup Before Migration** - نسخ احتياطي قبل أي تهجير
5. **Incremental Migrations** - تهجير تدريجي للبيانات الكبيرة

## 📊 أنواع التهجيرات

### 1. تهجير المخطط (Schema Migration)

**التعريف:** تغييرات على هيكل قاعدة البيانات

| العملية | الطريقة | مثال |
|---------|---------|------|
| إضافة جدول | `op.create_table()` | جدول جديد |
| حذف جدول | `op.drop_table()` | جدول مهمل |
| إضافة عمود | `op.add_column()` | عمود جديد |
| حذف عمود | `op.drop_column()` | عمود مهمل |
| تعديل نوع | `op.alter_column()` | تغيير نوع البيانات |
| إضافة فهرس | `op.create_index()` | تحسين الأداء |

**مثال: إضافة جدول جديد**

```python
def upgrade():
    op.create_table(
        'delayed_responses',
        sa.Column('id', sa.Integer(), nullable=False),
        sa.Column('user_id', sa.Integer(), nullable=True),
```

### 2. تهجير البيانات (Data Migration)

**التعريف:** نقل أو تحويل البيانات الموجودة

```python
def upgrade():
    # 1. إضافة عمود جديد
    op.add_column('verses', 
        sa.Column('normalized_text', sa.Text(), nullable=True)
    )
    
    # 2. ملء البيانات
    conn = op.get_bind()
    conn.execute("""
        UPDATE verses 
        SET normalized_text = LOWER(REGEXP_REPLACE(text_arabic, '[^\w\s]', '', 'g'))
        WHERE normalized_text IS NULL
    """)
    
    # 3. جعل العمود إجبارياً
    op.alter_column('verses', 'normalized_text', nullable=False)
```

### 3. تهجير البيانات الكبيرة (Large Data Migration)

**التعريف:** تهجير آلاف السجلات بأمان

**استراتيجية:**
- تقسيم إلى دفعات (Batches)
- تنفيذ في الخلفية (Background)
- متابعة التقدم (Progress Tracking)

**مثال: تهجير حصرياً**

```python
from tqdm import tqdm

def migrate_verses_batch():
    """تهجير الآيات على دفعات"""
    BATCH_SIZE = 500
    conn = op.get_bind()
    
    # حساب عدد الدفعات
    total = conn.execute("SELECT COUNT(*) FROM verses").scalar()
    batches = (total // BATCH_SIZE) + 1
    
    for i in tqdm(range(batches), desc="Migrating verses"):
        offset = i * BATCH_SIZE
        
        # جلب الدفعة
        batch = conn.execute(f"""
            SELECT id, text_arabic 
            FROM verses 
            ORDER BY id 
            LIMIT {BATCH_SIZE} OFFSET {offset}
        """).fetchall()
        
        # معالجة الدفعة
        for verse in batch:
            normalized = normalize_arabic(verse.text_arabic)
            conn.execute(f"""
                UPDATE verses 
                SET normalized_text = '{normalized}'
                WHERE id = {verse.id}
            """)
        
        # تسجيل التقدم
        print(f"Processed {min((i+1) * BATCH_SIZE, total)}/{total}")
```

## 🔁 استراتيجية Zero Downtime

### المبدأ: التهجير على مراحل

```
المرحلة 1: إضافة الهيكل الجديد (لا يؤثر على التطبيق)
المرحلة 2: نشر التطبيق الجديد (يدعم القديم والجديد)
المرحلة 3: تهجير البيانات تدريجياً
المرحلة 4: حذف الهيكل القديم (بعد التأكد من نجاح التهجير)
```

### مثال: إضافة عمود جديد

```python
# المرحلة 1: إضافة العمود nullable
def upgrade():
    op.add_column('interactions', 
        sa.Column('intensity', sa.String(20), nullable=True)
    )

# المرحلة 2: التطبيق يدعم null
# الكود يتعامل مع intensity = None

# المرحلة 3: ملء البيانات
def upgrade():
    conn = op.get_bind()
    conn.execute("""
        UPDATE interactions 
        SET intensity = 
            CASE 
                WHEN emotion_confidence > 0.85 THEN 'high'
                WHEN emotion_confidence > 0.7 THEN 'medium'
                ELSE 'low'
            END
        WHERE intensity IS NULL
    """)

# المرحلة 4: جعل العمود إجبارياً
def upgrade():
    op.alter_column('interactions', 'intensity', nullable=False)
```

## 🔄 سير العمل (Workflow)

### 1. إنشاء تهجير جديد

```bash
# 1. إنشاء ملف التهجير
alembic revision -m "description_of_change"

# 2. كتابة كود التهجير (upgrade/downgrade)

# 3. اختبار محلي
alembic upgrade head
alembic downgrade -1
```

### 2. اختبار في بيئة Staging

```bash
# 1. أخذ نسخة من قاعدة الإنتاج
pg_dump murassikh > backup.sql

# 2. استعادة في Staging
psql murassikh_staging < backup.sql

# 3. تطبيق التهجير
alembic upgrade head

# 4. اختبار التطبيق
pytest tests/

# 5. اختبار التراجع
alembic downgrade -1
```

### 3. تطبيق في الإنتاج

```bash
# 1. إشعار الفريق
# "بدء تهجير قاعدة البيانات - المتوقع: 5 دقائق"

# 2. نسخ احتياطي
pg_dump murassikh > pre_migration_backup_$(date +%Y%m%d).sql

# 3. تطبيق التهجير
alembic upgrade head

# 4. التحقق
alembic current

# 5. إشعار الفريق
# "تم التهجير بنجاح"
```

## 📚 أفضل الممارسات

1. **Always Test Downgrade** - اختبر التراجع دائماً
2. **Small Migrations** - تهجيرات صغيرة ومتكررة أفضل
3. **Transactional Migrations** - التهجيرات يجب أن تكون ذرية
4. **Document Everything** - وثّق كل تهجير بشكل واضح
5. **Backup Before Everything** - نسخ احتياطي قبل كل شيء
