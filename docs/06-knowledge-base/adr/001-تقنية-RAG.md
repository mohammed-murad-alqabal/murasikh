# ADR-001: استخدام تقنية RAG للنصوص الشرعية

## الحالة
مقبول ✅

## التاريخ
2026-09-11

## السياق

نحتاج إلى نظام يقدم توصيات دينية (آيات وآيات) للمستخدم بناءً على حالته العاطفية. التحدي الرئيسي هو ضمان دقة النصوص الشرعية ومنع توليد نصوص خاطئة (Hallucination) من قبل نماذج اللغة الكبيرة (LLMs).

### الخيارات المتاحة

1. **Zero-shot Generation**: السماح للـ LLM بتوليد النصوص الشرعية مباشرة
2. **Fine-tuned Model**: تدريب نموذج مخصص على النصوص الشرعية
3. **Retrieval-Augmented Generation (RAG)**: استرجاع النصوص من قاعدة بيانات ثم تقديمها للـ LLM

## القرار

استخدام **Retrieval-Augmented Generation (RAG)** مع القواعد الصارمة التالية:

### القواعد

1. **الاعتماد الحصري على محتوى موثق**
   - التفاسير الميسرة المعتمدة
   - الآيات الصحيحة فقط (الصحيحين + السنن)

2. **استبعاد التوليد العشوائي**
   - عدم السماح للـ LLM بتوليد أي نص شرعي من تلقاء نفسه
   - النص يجب أن يأتي حرفياً من قاعدة البيانات

3. **التحقق من المطابقة**
   - كل نص مقدم للـ LLM يجب أن يُقارن بالمصدر الأصلي
   - رفض أي نص لا يطابق المصدر بنسبة 100%

## التبرير

### لماذا RAG؟

| المعيار | RAG | Zero-shot | Fine-tuned |
|---------|-----|-----------|------------|
| دقة النصوص | ✅ عالية جداً | ❌ منخفضة | ⚠️ متوسطة |
| التكلفة | ✅ منخفضة | ✅ منخفضة | ❌ عالية |
| المرونة | ✅ عالية | ✅ عالية | ❌ منخفضة |
| الصيانة | ✅ سهلة | ✅ سهلة | ❌ صعبة |
| التحكم | ✅ كامل | ❌ محدود | ⚠️ جزئي |

### المخاطر التي يتجنبها

1. **Hallucination**: النموذج قد يولد آيات أو آيات غير صحيحة
2. **تفسير خاطئ**: النموذج قد يقدم تفسيراً غير دقيق
3. **تحريف النص**: النموذج قد يغير كلمات النص الأصلي

## التنفيذ

### البنية

```
[مستخدم] → [تحليل المشاعر] → [بحث دلالي] → [استرجاع النص] → [التحقق] → [الرد]
                                    ↓
                              [Vector DB]
                                    ↓
                           [قاعدة المعرفة الشرعية]
```

### المكونات

1. **Embedding Model**: GATE-AraBERT-v1
2. **Vector DB**: Chroma (تطوير) / Milvus (إنتاج)
3. **LLM**: Google Gemini (للتحليل والتلخيص فقط)
4. **قاعدة البيانات**: PostgreSQL (للمحتوى الأصلي)

### كود التحقق

```python
def validate_response(response: str, source_text: str) -> bool:
    """
    التحقق من أن النص الشرعي في الرد يطابق المصدر تماماً.
    """
    # تنظيف النصوص
    clean_response = response.strip()
    clean_source = source_text.strip()
    
    # التحقق من التطابق التام
    if clean_response == clean_source:
        return True
    
    # التحقق من أن المصدر موجود في الرد
    if clean_source in clean_response:
        return True
    
    # فشل التحقق
    logger.warning(f"Text mismatch:\nResponse: {clean_response}\nSource: {clean_source}")
    return False
```

## العواقب

### إيجابية

- ✅ ضمان دقة النصوص الشرعية
- ✅ إمكانية الرجوع للمصدر الأصلي
- ✅ سهولة تحديث قاعدة المعرفة
- ✅ تقليل المخاطر الشرعية

### سلبية

- ⚠️ حاجة لتجهيز قاعدة بيانات شاملة
- ⚠️ تكلفة إضافية للـ Vector DB
- ⚠️ وقت إعداد أولي أطول

### محايدة

- يتطلب فريق مراجعة شرعية للتحقق من المحتوى

## البدائل المرفوضة

### Zero-shot Generation

**سبب الرفض:** مخاطر عالية جداً من:
- توليد آيات غير موجودة
- تحريف النصوص الشرعية
- تفسيرات غير صحيحة

### Fine-tuned Model

**سبب الرفض:**
- تكلفة تدريب عالية
- صعوبة التحديث
- لا يضمن الدقة 100%
