# ADR-002: اعتماد Offline-First Architecture

## الحالة
مقبول ✅

## التاريخ
2026-09-11

## السياق

مشروع مُرَسِّخ يقدم دعماً روحياً ونفسياً للمستخدم. قد يحتاج المستخدم للوصول للتوصيات في أوقات أو أماكن لا يتوفر فيها اتصال بالإنترنت.

### التحديات

1. **الاتصال غير المضمون**: قد ينقطع الإنترنت في أي لحظة
2. **الخصوصية**: بعض المستخدمين يفضلون عدم الإرسال المستمر للبيانات
3. **الأداء**: التطبيق يجب أن يكون سريعاً حتى مع ضعف الإنترنت
4. **حجم البيانات**: المحتوى الشرعي كبير (6236 آية قرآنية)

## القرار

اعتماد **Offline-First Architecture** حيث قاعدة البيانات المحلية هي المصدر الأساسي.

### المبادئ

1. **المصدر المحلي أولاً** - Hive/Drift للتخزين المحلي
2. **الشبكة للتحسين** - وليست شرطاً للعمل
3. **مزامنة خلفية** - بدون تدخل المستخدم

## التنفيذ

### البنية

```
Flutter App
    ↓
Repository Layer
    ↓
Local Data (Hive) ← Source of Truth
    ↓
Remote API → Sync Target
```

### البيانات المخزنة محلياً

| النوع | الحجم | الأولوية |
|-------|-------|----------|
| الآيات الأساسية | ~2 MB | عالية |
| الآيات الأساسية | ~5 MB | عالية |
| التفاسير المختصرة | ~3 MB | متوسطة |
| سجل التفاعلات | ~1 MB | متوسطة |

**الحجم الإجمالي:** ~11 MB

## العواقب

### إيجابية ✅
- تجربة مستخدم ممتازة بدون انتظار
- يعمل في جميع الظروف
- خصوصية أفضل للبيانات
- استجابة فورية (< 100ms)

### سلبية ⚠️
- حجم تطبيق أكبر
- تعقيد إضافي في التطوير
- حاجة لإدارة تعارضات البيانات
