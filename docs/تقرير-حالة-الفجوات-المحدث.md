# تقرير محدث عن حالة فجوات Backend والخطط

**تاريخ الفحص:** 2026-09-16  
**الفرع:** `main`  
**آخر commit مفحوص:** `6393060`  
**المستودع:** `mohammed-murad-alqabal/murasikh`

## الحكم المختصر

لم تُغلق جميع الفجوات والبنود. توجد تغييرات حقيقية منذ الفحص السابق، أهمها إضافة أساس JWT، وتفعيل Rate Limiting، وعودة ملفات مصدر Flutter، وإضافة العمر والجنس إلى إعدادات المستخدم. لكن **Alembic Migrations غير موجودة**، ومصادقة JWT ما زالت أساساً أولياً غير مدمج لحماية بقية الـ endpoints، كما أن فجوات الاسترجاع الموزون، حذف الأحاديث، الاختبارات، وبيئة الإنتاج ما زالت قائمة.

## Alembic Migrations

| العنصر | الحالة | الدليل |
|---|---|---|
| حزمة Alembic في الاعتماديات | موجودة | `backend/requirements.txt` يحتوي `alembic==1.19.2` |
| `alembic.ini` | غير موجود | لا يظهر في ملفات المستودع |
| مجلد Alembic أو migrations | غير موجود | لا توجد مسارات `alembic/` أو `migrations/` أو `versions/` |
| `env.py` | غير موجود | لا يوجد ملف إعداد لربط Alembic بنماذج SQLAlchemy |
| ملفات revisions | غير موجودة | لا توجد ملفات ترحيل للإصدارات |
| أمر تشغيل الترحيلات في Docker/CI | غير موجود | لا يوجد `alembic upgrade head` في الإعدادات التشغيلية |

**النتيجة:** لم يتم إنشاء Alembic Migrations. إضافة الحزمة فقط لا تعني إعداد الترحيلات.

## JWT والمصادقة

### ما تم إنجازه

- تمت إضافة `backend/app/core/auth.py` وفيه إنشاء والتحقق من JWT باستخدام `PyJWT` و`HS256`.
- تمت إضافة `backend/app/api/v1/endpoints/auth.py` وفيه `/register` و`/login`.
- تمت إضافة `OAuth2PasswordBearer` وقراءة المستخدم الحالي عبر `get_current_user`.
- تمت إضافة `passlib` و`bcrypt` لتجزئة كلمات المرور والتحقق منها.
- تمت إضافة `slowapi` وتسجيل Rate Limiting في `main.py`.
- تمت إضافة واجهة Flutter للمصادقة وحفظ الرمز في `SharedPreferences`.

### ما لم يكتمل

| الفجوة | الحالة | الدليل أو الأثر |
|---|---|---|
| ربط JWT بقاعدة بيانات المشروع | غير مكتمل | `UserManager` يستخدم SQLite مستقلة (`users.db`) بينما نماذج المشروع تستخدم SQLAlchemy/PostgreSQL |
| حماية التوصية والتاريخ بالتوكن | غير مكتمل | `get_current_user` معرّفة، لكن لا توجد استخدامات لها في endpoints الأخرى |
| إرسال Bearer token من Flutter إلى API | غير مكتمل | `ApiService` يرسل الطلبات دون ترويسة `Authorization` |
| سر JWT في الإنتاج | غير آمن افتراضياً | `auth.py` يستخدم قيمة fallback ثابتة إذا لم يوجد `JWT_SECRET_KEY` |
| اختبارات JWT | غير موجودة | لا توجد اختبارات فعلية للتسجيل، الدخول، انتهاء التوكن، أو رفض التوكن غير الصحيح |
| توحيد التخزين | غير مكتمل | توجد نماذج SQLAlchemy و`UserManager` مبني على SQLite، ما يخلق مسارين مختلفين للمستخدمين |

**النتيجة:** تم بناء أساس JWT، لكنه ليس نظام مصادقة متكاملاً ومطبقاً على التطبيق كله.

## الفجوات السابقة بعد آخر تحديث

| البند | الحالة الحالية |
|---|---|
| واجهة Flutter | تحسن واضح؛ يوجد الآن `frontend/lib` وملفات الشاشات والخدمات والاختبارات |
| العمر والجنس | منفذ في `UserSettings` و`SettingsService` وواجهة المعلومات الشخصية |
| Alembic | غير منفذ |
| JWT | منفذ كأساس، غير مكتمل كتكامل شامل |

| الاسترجاع الموزون المطلوب | غير مكتمل؛ لا توجد `search_by_emotion_weighted` أو `VerseEmotion`، والمستخدم هو `verse_fingerprints.json` القديم/المحلي |
| توليد أوزان Gemini المكتملة | غير مثبت؛ يوجد السكريبت فقط ولا يوجد ناتج Gemini نهائي موثق |
| PostgreSQL وRedis في Compose | غير منفذين؛ `docker-compose.yml` يشغل Backend فقط |
| Celery | غير موجود |
| Prometheus/Grafana/Sentry | غير موجودة |
| الاختبارات | غير كافية؛ لا توجد اختبارات Auth أو Alembic أو الاسترجاع الموزون أو منع الأحاديث |
| تشغيل الاختبارات محلياً | تعذر؛ `pytest` وFlutter غير مثبتين في بيئة الفحص، مع نجاح `compileall` لملفات Python |
| دوال غير مكتملة | ما زالت توجد دوال `pass` في خدمات القرآن والأحاديث وتحليل الصوت |

## ملاحظة على علامات الإنجاز في الخطط

بعض بنود `todo-1.md` أصبحت موسومة بـ`[x]`، لكن الفحص الفعلي لا يثبت تنفيذها جميعاً. مثال ذلك أن الخطة تشير إلى تشغيل Redis أو بديله، بينما ملف Compose لا يشغل Redis، كما أن CI لا يشغل الترحيلات ولا يثبت اختبارات المصادقة. لذلك يجب اعتبار علامات `[x]` حالة توثيقية تحتاج إلى اختبارات وأدلة تشغيلية، وليست دليلاً كافياً على اكتمال البند.

## الأولويات اللازمة لإغلاق الفجوات

1. إنشاء `alembic.ini` و`alembic/env.py` وأول revision وربطها بقاعدة PostgreSQL.
2. نقل `UserManager` إلى SQLAlchemy/PostgreSQL أو توثيق SQLite كخيار مقصود وربطه ببقية النظام.
3. إضافة `Depends(get_current_user)` إلى endpoints التي تتطلب حساباً، مع تحديد المسارات العامة صراحةً.
4. إضافة طبقة HTTP في Flutter ترسل `Authorization: Bearer <token>` وتتعامل مع انتهاء التوكن.
5. منع fallback السري في الإنتاج وفرض `JWT_SECRET_KEY` من البيئة.
6. إضافة اختبارات تسجيل الدخول والتسجيل والتوكنات والصلاحيات.
7. تنفيذ `purge_hadiths.py` والتحقق من ChromaDB بعد التنظيف.
8. إكمال الاسترجاع الموزون وربطه بمخرجات الأوزان الفعلية، ثم إضافة اختبارات قبول له.
9. إضافة PostgreSQL وRedis أو توثيق البديل المعتمد فعلياً، ثم تشغيل فحوصات CI دون السماح بتمرير فشل الاختبارات.

## الخلاصة النهائية

**لا، لم يتم إصلاح كل الفجوات والبنود.**

الإجابة الدقيقة على السؤالين هي:

- **هل أنشئت Alembic Migrations؟** لا. تم تثبيت الحزمة فقط، ولا توجد ملفات ترحيل أو إعداد Alembic.
- **هل أُعدت JWT؟** أُضيف أساس JWT ومسارا التسجيل والدخول، لكن التكامل غير مكتمل؛ فلا توجد حماية فعلية لبقية المسارات، ولا يرسل Flutter التوكن مع الطلبات، ولا يوجد توحيد مع قاعدة PostgreSQL أو اختبارات مصادقة.
